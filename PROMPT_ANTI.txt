 PHẦN 1: SỬA LỖI NGHIÊM TRỌNG (BẮT BUỘC LÀM TRƯỚC)
============================================================

1.1. SỬA FILE `server/prisma/schema.prisma`
- File hiện tại bị DUPLICATE nhiều enum và model. Cụ thể:
  * Enum `Role` khai báo USER, ADMIN, SALES 2 lần → Xóa trùng, giữ 1 lần
  * Enum `VehicleStatus` khai báo AVAILABLE, RESERVED, SOLD 2 lần → Xóa trùng, thêm UNAVAILABLE
  * Enum `PaymentMethod` khai báo CASH 2 lần → Xóa trùng
  * Enum `DepositStatus`, `QuotationStatus`, `InvoiceStatus` xuất hiện 2 lần (1 lần có comment, 1 lần không) → Giữ lại phần có comment, xóa phần trùng
  * Model `Payment` xuất hiện 2 lần (lần 1 đơn giản, lần 2 có thêm invoiceId, depositId) → Giữ lại lần 2 (đầy đủ hơn), xóa lần 1
  * Model `User` có fields bị duplicate (myLeads, assignedLeads, testDrives, deposits, quotations, invoices khai báo 2 lần) → Xóa trùng
  * Model `Vehicle` có fields bị duplicate (id, brandId, categoryId... khai báo 2 lần) → Giữ phần đầy đủ hơn (có vin, trim, condition, costPrice, drivetrain, interiorColor, warrantyInfo, isDeleted, deletedAt), xóa phần trùng
  * Model `Lead` có fields bị duplicate (vehicleId, customerId, assignedToId, guestName...) → Xóa trùng
  * Model `Deposit` có relation bị duplicate → Xóa trùng
  * Model `Invoice` có relation bị duplicate → Xóa trùng
  * Model `FinanceApplication` có fields bị duplicate → Xóa trùng
- Hãy tạo lại file schema.prisma HOÀN CHỈNH, KHÔNG DUPLICATE, với tất cả models:
  User, Brand, Category, Vehicle, VehicleImage, Lead, TestDrive, FinanceApplication, Deposit, Quotation, Invoice, Payment, Promotion, BlogPost, Notification, AuditLog, CustomerInteraction
- Mỗi model phải có đầy đủ @@index cho các trường hay query
- Sử dụng @@map cho tên bảng snake_case

1.2. SỬA FILE `server/prisma/seed.ts`
- File hiện tại bị duplicate code cũ + mới xen kẽ (ví dụ biến `admin` vs tạo user mới, `vehicle` vs `v1`)
- Hãy viết lại hoàn chỉnh seed.ts với:
  * Dọn dẹp dữ liệu cũ đúng thứ tự foreign key
  * Tạo 3 users: 1 Admin, 2 Sales
  * Tạo 6 Brands (Ford, Toyota, Mercedes-Benz, VinFast, Porsche, Audi)
  * Tạo 5 Categories (SUV, Sedan, Coupe, EV, MPV)
  * Tạo 6-8 Vehicles mẫu với thông số kỹ thuật thực tế Việt Nam (giá VNĐ), kèm ảnh
  * Tạo 3-4 Leads mẫu
  * Tạo 2 TestDrive mẫu
  * Tạo 2 Promotions mẫu
  * Tạo 1 BlogPost mẫu
  * Tạo 1 Deposit mẫu + 1 Quotation mẫu + 1 Invoice mẫu

 PHẦN 2: THÊM ZOD VALIDATION CHO TẤT CẢ MODULES
============================================================

Tạo các file validation trong `server/src/validations/`:
- `vehicle.validation.ts`: createVehicleSchema, updateVehicleSchema (validate: model, year >= 2000, price > 0, fuelType enum, transmission enum, color required...)
- `lead.validation.ts`: createLeadSchema (guestPhone bắt buộc, guestName bắt buộc, type enum)
- `testdrive.validation.ts`: createTestDriveSchema (customerName, customerPhone, scheduledDate phải là future date)
- `deposit.validation.ts`: createDepositSchema, updateDepositStatusSchema
- `quotation.validation.ts`: createQuotationSchema (vehiclePrice, totalAmount required, validUntil future date)
- `invoice.validation.ts`: createInvoiceSchema, updateInvoiceStatusSchema
- `finance.validation.ts`: createFinanceSchema (loanAmount > 0, loanTermMonths > 0)
- `payment.validation.ts`: createPaymentSchema (amount > 0, method enum)
- `user.validation.ts`: updateUserSchema (role chỉ ADMIN mới đổi được)
- `blog.validation.ts`: createBlogPostSchema, updateBlogPostSchema
- `promotion.validation.ts`: createPromotionSchema (startDate < endDate, discountValue > 0)

Mỗi validation file export cả createSchema và updateSchema (update dùng .partial()).
Sử dụng middleware `validate(schema)` đã có sẵn tại `server/src/middlewares/validate.middleware.ts` để gắn vào routes.

 PHẦN 3: THÊM API ROUTES CÒN THIẾU
============================================================

3.1. Blog API (`server/src/controllers/blog.controller.ts` + `server/src/routes/blog.route.ts`):
- GET /api/blogs — List blog posts (public, chỉ isPublished=true, pagination, search by title)
- GET /api/blogs/:slug — Get blog post by slug (public)
- POST /api/blogs — Create blog post (ADMIN only)
- PUT /api/blogs/:id — Update blog post (ADMIN only)
- DELETE /api/blogs/:id — Delete blog post (ADMIN only)
- PATCH /api/blogs/:id/publish — Toggle publish (ADMIN only)

3.2. Promotion API (`server/src/controllers/promotion.controller.ts` + `server/src/routes/promotion.route.ts`):
- GET /api/promotions — List promotions (public, filter active)
- GET /api/promotions/:id — Get promotion detail
- POST /api/promotions — Create (ADMIN only)
- PUT /api/promotions/:id — Update (ADMIN only)
- DELETE /api/promotions/:id — Delete (ADMIN only)

3.3. Notification API (`server/src/controllers/notification.controller.ts` + `server/src/routes/notification.route.ts`):
- GET /api/notifications — List notifications cho user hiện tại (authenticate)
- PATCH /api/notifications/:id/read — Mark as read
- PATCH /api/notifications/read-all — Mark all as read
- GET /api/notifications/unread-count — Đếm số thông báo chưa đọc

3.4. AuditLog API (`server/src/controllers/auditlog.controller.ts` + `server/src/routes/auditlog.route.ts`):
- GET /api/audit-logs — List audit logs (ADMIN only, pagination, filter by entity/user/date range)

Đăng ký tất cả routes mới vào `server/src/app.ts`.

- `payment.service.ts`: Logic cập nhật status Invoice/Deposit khi payment COMPLETED
- `notification.service.ts`: Helper tạo notification cho user cụ thể

Refactor controllers để gọi service thay vì gọi Prisma trực tiếp.
